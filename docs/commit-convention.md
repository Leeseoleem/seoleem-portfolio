# 커밋 컨벤션

> seoleem portfolio의 커밋 규칙. 모든 커밋은 이 형식을 따른다.
> 핵심 규칙은 `CLAUDE.md`에도 요약돼 있으며, 이 문서가 원본이다.

---

## 1. 형식

```
태그: 설명
```

- 설명은 한국어 OK, 50자 이내
- 본문은 "왜" 변경했는지가 자명하지 않을 때만 작성
- 본문이 필요하면 관련 결정 기록을 링크한다 (`docs/log/` 하위)

---

## 2. 태그

| 태그 | 용도 |
|---|---|
| feat | 새 기능 추가 |
| fix | 버그 수정 |
| refactor | 동작 변경 없는 코드 개선 |
| style | 포맷팅 등 비기능 변경 |
| chore | 빌드·설정·패키지 관리 |
| docs | 문서만 변경 |
| test | 테스트 추가·수정 |

기본 7종만 사용한다. 임의 신설 금지.

---

## 3. 운영 규칙

- 단계별로 커밋 — 하나의 논리 단위(파일 생성, 기능 구현, 설정 변경)마다 커밋
- 여러 변경이 섞인 채 커밋 금지. 작업 도중에도 중간 커밋
- 검증 명령(`CLAUDE.md`의 코드 리뷰 섹션 참조) 실패 상태로 커밋 금지

---

## 4. 톤·금지

- 이모지 금지
- 과장·과한 표현 금지
- 부드러운 단언 금지. 강조는 실제 중요한 지점에만
- 커밋·주석은 반말 문어체로 작성

---

## 5. AI 트레일러·푸터 금지

커밋 메시지에 도구가 자동으로 붙이는 흔적을 남기지 않는다.

- `Co-Authored-By: Claude ...` 트레일러 금지
- `Generated with Claude Code` 등 푸터 금지

위임 프롬프트로 작업을 맡길 때는 이 두 항목을 프롬프트에 명시한다. 도구가 기본값으로 붙이는 경우가 있어, 본문 규칙만으로는 누락될 수 있다.

---

## 6. 위임 작업 시 추가 금지

AI에게 커밋까지 위임할 때 함께 명시하는 항목.

- `cd && git` 패턴 금지 (작업 디렉토리 이동 후 git 실행 형태)
- 한 커밋에 여러 변경 섞기 금지 (3번 운영 규칙과 동일하지만 위임 시 재강조)

---

## 7. 예시

```
feat: XP 부팅 화면과 모니터 카메라 전환 구현
fix: 고해상도 화면에서 오브젝트 클릭 좌표 어긋남 수정
refactor: 책상 오브젝트를 DeskObject 컴포넌트로 분리
style: 고양이 컴포넌트 포맷 정리
chore: 디자인 토큰 xp / toss 접두 분리
docs: 사이클 01 회고 추가
test: 사운드 훅 사용자 제스처 전 재생 차단 테스트 추가
```

---

## 8. 브랜치·PR 연결

- `main`은 배포 브랜치. 직접 커밋하지 않는다
- `dev`는 통합 브랜치. 작업 브랜치는 `dev`에서 파고 `dev`로 PR
- 작업 브랜치 이름은 `feat/xxx`, `fix/xxx`, `chore/xxx`
- 배포는 `dev` → `main` PR
- 브랜치 전략 원본은 `CLAUDE.md`
- PR 제목도 커밋과 동일한 `태그: 설명` 형식을 사용한다
